# GameGate 产品需求基线

- 版本：v0.1
- 更新日期：2026-11-02
- 状态：需求整理稿，可作为后续设计与拆分任务的依据；不是全部细节已经批准的实现规格。
- 目标读者：产品、设计、客户端、核心适配与测试人员。
- 本文区分用户明确决定、按讨论整理的需求规则，以及尚待确认的实施建议。存在历史建议冲突时，以本文中的最新明确决定为准。

## 1. 产品定位

GameGate 是基于 RetroArch 二次开发的跨平台复古游戏平台。通过第三方游戏资源源、游戏资料源和模拟器核心仓库，提供游戏发现、下载、管理以及应用内游玩的统一体验。

目标覆盖 Android、iOS／iPadOS、原生鸿蒙、Windows、Linux、macOS。六端是产品目标，不表示六端同步首发，也不表示同一核心在全部设备上都可用。

目标用户包括希望简化配置的普通复古游戏玩家，以及需要管理本地游戏、切换资源源和运行核心的进阶用户。

核心用户流程：

> 添加资源源 → 浏览或搜索游戏 → 查看统一资料及兼容性 → 下载游戏并准备核心 → App 内游玩 → 返回游戏库。

用户也应能通过本地导入进入游戏库，不依赖在线资源源完成全部操作。

## 2. 已确认的产品与技术决策

| 编号 | 决定 | 说明 |
|---|---|---|
| D-01 | 所有游戏只能在 App 内运行 | 不提供跳转外部模拟器的运行模式，不将外部启动作为不兼容平台的降级方案 |
| D-02 | 基于 RetroArch 二次开发 | 已接受该方向，不再把自建宿主列为当前并行选型任务 |
| D-03 | 接受 GPL-3.0 开源分发义务 | 保留上游版权与许可信息，按适用义务提供对应源码；核心等第三方组件分别核查许可 |
| D-04 | 不考虑 Rust | 不开展 C → Rust 迁移，沿用现有 C／C++ 生态 |
| D-05 | 核心插件化 | App 提供运行与兼容能力，核心执行游戏；普通独立模拟器安装包不等于可加载核心插件 |
| D-06 | 第三方托管为目标 | 游戏文件和核心尽量由第三方提供；客户端允许本地下载、安装、缓存与保存 |
| D-07 | 增加统一游戏资料能力 | 统一名称、简介等信息，避免不同资源源造成游戏资料混乱 |
| D-08 | 支持资料多语言 | 界面翻译、游戏资料语言、ROM 内容语言分开管理 |
| D-09 | 转入二开，停止追加上游通用验证 | 后续测试聚焦新增／修改功能及其影响；不代表免除回归或跨端适配测试 |

受限平台是否允许核心随 App 打包，用户尚未确认；不得将“尽量第三方托管”解读为已同意所有平台采用随包核心。

## 3. 三类外部来源

| 类型 | 提供内容 | 不承担的职责 |
|---|---|---|
| 游戏资源源 | 游戏目录、版本说明、下载地址、大小、校验信息，以及可选外部资料 ID | 不直接决定执行代码权限或覆盖统一游戏资料 |
| 游戏资料源 | 名称、别名、简介、封面、截图、开发商、发行信息及语言信息 | 不等于 ROM 下载授权，也不承担核心安装 |
| 核心仓库 | 核心包、版本、平台架构、接口兼容性、来源验证信息与许可证 | 不等于游戏内容仓库 |

三者独立配置与更新。一个游戏文件可来自不同资源源，一份作品资料可关联多个发行版本，同一主机平台可由多个兼容核心支持。

默认是否附带源地址、是否提供官方推荐源目录，尚未决定。开发用合法测试源不自动成为产品默认源。

## 4. 功能需求

下列内容是按讨论整理的目标需求。具体首版纳入项见第 8 节，接口格式与数据表属于后续详细设计。

### F-01 游戏库

- 支持本地导入和下载完成后的入库。
- 显示封面、首选名称、主机平台、安装及运行状态。
- 支持搜索、平台分类、收藏和最近游玩。
- 原文名与别名参与搜索，不只匹配界面当前语言。
- 区分同作品不同平台、地区、版本和文件，避免仅按名称合并。
- 删除资源源不自动删除本地游戏、资料关联或存档。
- 删除游戏文件与删除存档分别处理，操作时明确影响范围。

### F-02 游戏资源源

- 支持通过地址添加源，以及启用、停用、刷新和移除。
- 展示来源身份、协议版本、更新状态与失败原因。
- 按源能力提供目录、搜索、详情和下载信息。
- 外部资料 ID 应附带资料提供者名称，不接受无命名空间的通用 ID。
- 单个源失败不影响其他源及已安装游戏。
- 来源返回的信息视为外部数据，不能直接执行任意命令或改变宿主配置。

首版建议采用声明式 JSON 协议；是否支持本地配置文件导入、鉴权及后续脚本扩展，在协议设计时确定。JSON 首版路线尚未单独获批。

### F-03 下载与文件管理

- 统一展示下载队列、进度、取消、失败重试及目标存储位置。
- 源服务器支持时提供断点续传；不支持时允许重新下载并明确说明。
- 下载前检查可用空间与已知平台限制；下载后检查可用校验信息。
- 核心包的完整性和发布者验证规则独立于游戏文件规则，不能仅凭文件名加载。
- 安全处理压缩包路径、解压空间和异常文件；失败内容不得被标记为可运行。
- 下载、解压、核心安装与最终可运行状态分开显示。
- 已下载且依赖齐备的游戏可离线启动。

### F-04 核心管理

- 识别已安装核心，显示名称、版本、适用主机平台和当前设备兼容性。
- 支持获取、安装、更新与卸载；受限平台的可用操作按实际能力呈现。
- 核心清单至少描述核心 ID、版本、操作系统、CPU 架构、宿主接口要求、支持格式、BIOS 要求、下载地址及许可证。
- 安装前检查兼容性，校验通过后才进入可用状态。
- 更新前明确存档兼容风险并保留可恢复路径；具体版本保留策略后续设计。
- 核心卸载不静默删除游戏文件和用户存档。
- 原生核心并非安全沙箱，加载前应有明确的信任与来源策略。

### F-05 应用内运行与统一体验

- 游戏详情提供统一的“开始游戏”入口。
- 启动前检查游戏文件、兼容核心、BIOS 和必要权限。
- 缺少核心或 BIOS 时给出针对性提示，不跳转外部模拟器。
- 复用 RetroArch 已有加载、运行、输入、音视频及生命周期能力。
- 统一提供暂停、继续、输入设置、画面设置和退出入口。
- 游戏内存档与即时存档分开管理，关联游戏文件、核心与必要版本信息。
- 即时存档、快进、倒带等按能力展示，不承诺所有核心均支持。
- 正常退出回到游戏库；异常退出后再次打开应能识别失败会话，不伪称存档成功。
- 不将不同系统的二进制兼容性、存档兼容性和游戏兼容性混为一谈。

### F-06 游戏资料与匹配

统一资料字段建议包括：名称、原文名、别名、简介、主机平台、地区发行信息、开发商、发行商、类型、玩家人数、封面、截图、外部资料 ID、来源和更新时间。

匹配原则：

1. 优先使用带提供者命名空间的资料 ID，同时核对主机平台和版本语义。
2. 资料服务支持文件识别时，可使用 ROM 校验值；压缩包与内部 ROM 分别计算，不能混用。
3. 再依据名称、别名、平台和地区筛选候选。
4. 无足够依据时保留未匹配状态或让用户选择，不强制自动关联。
5. 支持手动纠正、解除匹配和重新匹配。
6. 用户手动修改的字段不被后台刷新覆盖。
7. 资料服务不可用不影响已经具备运行依赖的本地游戏。

首选评估 ScreenScraper 和 IGDB，但尚未决定实际提供者。其他候选见第 11 节。服务的 API 配额、缓存、图片、翻译和商业使用条款需在接入前核实。

## 5. 多语言需求

### L-01 区分三层语言

| 层级 | 示例 | 管理方式 |
|---|---|---|
| App 界面 | 开始游戏、下载、设置 | 复用 RetroArch 消息国际化机制，为新增功能增加翻译 |
| 游戏资料 | 名称、简介、别名 | 按语言保存内容，由资料源、人工编辑或后续翻译能力提供 |
| 游戏本身 | ROM 内对白、菜单 | 取决于游戏文件版本，切换界面语言不改变 ROM 内容 |

### L-02 界面国际化

- 首版建议完整维护简体中文和英文，具体语言发布承诺待确认。
- 保留上游其他语言能力，新增文案缺失时回退到基础英文。
- 不在新增界面中写死面向用户的中文字符串。
- 遵守上游生成流程；部分语言表由脚本生成，不能直接修改后假定同步不会覆盖。
- GameGate 自有文案需有独立可维护的来源和同步策略，不依赖获得上游 Crowdin 管理权限。
- 检查字体、换行、按钮长度和布局适配。

### L-03 游戏资料语言

- 设置“游戏资料偏好语言”，默认跟随界面语言，允许单独选择。
- 采用 BCP 47 语言标识，例如 `en`、`ja`、`zh-Hans`、`zh-Hant`。
- 同一游戏身份关联多份语言文本，不因翻译生成重复游戏记录。
- 每个本地化字段保留语言、来源、更新时间及来源性质。
- 名称、简介分别匹配和回退，不要求整页同语言或同资料源。
- 建议回退顺序：用户自定义内容 → 首选语言 → 备用语言 → 原文；名称仍缺失时使用源标题或文件名，简介仍缺失时显示暂无资料。
- 回退后展示实际语言，不能把英文简介标记为中文。
- 保留原文名称和别名，全部可参与搜索。

### L-04 名称来源与翻译

- 区分官方本地化名、原名、社区译名、其他别名和用户自定义名。
- 不把任意中文别名直接认定为官方中文名。
- 不自动机器翻译游戏名并替换主名称。
- 简体转繁体不等于对应地区的官方译名。
- 简介机器翻译为后续建议，不作为首版必备能力。
- 如后续增加翻译，应保留原文，标注机器翻译，按原文版本缓存，并核实是否允许向翻译服务传输内容。

## 6. 核心数据概念

此处定义业务含义，不指定数据库技术或最终表结构。

| 对象 | 含义与关键关系 |
|---|---|
| 游戏作品 | 内部稳定 ID，关联外部资料 ID 与多语言内容 |
| 平台／发行版本 | 关联作品，描述主机平台、地区及适用版本信息；具体拆分粒度待设计 |
| 游戏文件 | 用户实际持有的 ROM、镜像或归档，记录路径、格式和校验值，关联发行版本 |
| 游戏资源记录 | 对应源内 ID、下载地址和源提供的信息；不取代作品身份 |
| 本地化资料字段 | 内容、语言、来源、时间、是否人工覆盖或机器翻译 |
| 核心包／已安装核心 | 标识、版本、架构、接口兼容性与安装位置 |
| 游戏运行配置 | 关联具体游戏文件与核心，包括用户覆盖项 |
| 存档 | 区分游戏内存档和即时存档，关联内容身份及必要的核心／版本信息 |
| 下载任务 | 资源目标、进度、阶段、校验结果和错误原因 |

外部资料库 ID 不作为唯一内部主键，防止服务更换或合并记录后丢失游戏库关联。匹配资料失败不阻止管理本地文件。

## 7. 状态与异常处理

游戏可出现以下状态：仅有目录信息、下载中、下载失败、待解压／校验、缺少核心、核心不兼容、缺少 BIOS、可运行、运行中、运行失败。

下载进度、资料匹配状态和运行就绪状态是不同维度，不强行用一个状态字段表达全部情况。资料尚未匹配的本地游戏，在依赖齐备时仍可运行。

| 场景 | 预期行为 |
|---|---|
| 资源源离线 | 标明源不可用，保留本地游戏和可用缓存 |
| 资料源限流或失败 | 可重试，保留旧资料，不阻断游玩 |
| 匹配不确定 | 显示候选或未匹配，允许人工纠正 |
| 文件校验失败 | 不进入就绪状态，说明失败并提供重试 |
| 核心架构不兼容 | 阻止安装或运行，说明支持范围 |
| 当前系统不允许所需安装方式 | 明确显示不可用，不暗中跳转外部应用 |
| 核心不支持即时存档 | 禁用或隐藏该能力，不提示保存成功 |
| 本地存储不足 | 在相关阶段中止并明确说明，不遗留伪成功记录 |

## 8. 首版建议范围（尚待整体确认）

| 优先级 | 建议内容 |
|---|---|
| P0 | Windows x64 首个开发端；本地游戏库；资源源管理；下载；核心管理；App 内运行闭环 |
| P0 | 一个游戏资料服务；基本匹配与人工纠正；按条款缓存；多语言字段和回退 |
| P0 | 简体中文／英文新增界面文案；明确的失败状态；不覆盖手动资料 |
| P1 | 更多资料提供者、跨源按字段补充、更多主机核心和平台适配 |
| 后续 | 简介机器翻译、账户、社区、云同步、联机、主题市场、任意脚本源 |

第一批主机平台候选为 FC／NES、GB／GBC、GBA、SFC／SNES、MD，最终核心与测试内容名单尚未确定。

Windows 优先、JSON 源协议、首版具体 UI 和中英文发布范围均为实施建议，不应据本表声称用户已经逐项确认。

## 9. 验收标准草案

验收聚焦二开改动及影响范围，不继续对上游所有已有能力进行全面探索。

| 编号 | 场景 | 通过条件 |
|---|---|---|
| A-01 | 添加合法测试源 | 成功解析支持的协议，显示目录与来源；错误协议有明确提示 |
| A-02 | 下载到运行 | 文件及核心满足条件后可在同一 App 内运行；退出返回游戏库 |
| A-03 | 本地导入与离线 | 具备运行依赖的已导入游戏，断网和应用重启后仍可启动 |
| A-04 | 缺少依赖 | 缺少核心、BIOS 或架构不兼容时准确说明，不误报可运行 |
| A-05 | 资料匹配 | 使用确定测试数据验证 ID 匹配、名称候选和手动纠正；同名不同平台不误合并 |
| A-06 | 多语言 | 界面切换后固定文案变化；资料按偏好逐字段回退；ROM 内容语言不受影响 |
| A-07 | 用户修改 | 修改名称／简介后刷新资料，用户覆盖值保持，仍能追溯原资料 |
| A-08 | 服务失败 | 单个资源或资料服务失败不影响其他来源及已安装游戏 |
| A-09 | 文件失败 | 下载中断、校验失败或解压失败均可识别，不产生错误的就绪状态 |
| A-10 | 数据保留 | 移除源或卸载核心不静默删除游戏存档；删除操作的范围可理解 |
| A-11 | 受影响运行回归 | 若改动触及输入、音视频、生命周期或存档，执行对应场景回归并记录限制 |
| A-12 | 许可与凭据 | 保留必要版权许可信息；不在客户端硬编码必须保密的资料服务凭据 |

性能指标、支持设备清单及存档兼容矩阵需随首版范围制定，不以未经测试的数值作为承诺。

### 建议阶段

1. **首版设计**：确认首发端、UI 接入方式、核心与资料提供者，以及源协议范围。输出页面职责、数据模型和接口协议。
2. **仓库准备**：在保留现有文档的前提下建立 GameGate 开发仓库，保留上游历史和许可信息，固定基线、区分产品分支及上游同步。
3. **本地闭环**：游戏库、本地导入、核心选择、应用内启动与返回。
4. **在线获取**：游戏源、核心仓库、下载与失败恢复。
5. **统一资料**：资料服务、匹配纠正、多语言和缓存；与前一阶段共用稳定的内部 ID。
6. **首版收敛**：受影响回归、许可材料、打包、使用说明，再推进其他端。

本阶段不再比较 Rust 迁移或外部模拟器启动方案。UI 框架、具体语言资源扩展方式与源码改造位置仍需结合上游结构设计。

## 12. 待确认事项及影响

| 编号 | 未决事项 | 建议或影响 |
|---|---|---|
| Q-01 | 首版是否 Windows x64 优先 | 建议是；其他端仍保留在产品目标中 |
| Q-02 | 首版 UI 方案及交互范围 | 确定 RetroArch 菜单扩展、定制界面和游玩菜单的边界后再实现 |
| Q-03 | 首批主机平台与核心 | 决定包体、兼容性、BIOS 和许可证工作 |
| Q-04 | 是否采用 JSON 源协议作为首版 | 建议先声明式协议，任意脚本后续讨论 |
| Q-05 | 首个游戏资料服务 | 结合中文覆盖、ROM 匹配、鉴权和条款选择 |
| Q-06 | 是否部署资料请求代理服务 | 取决于提供者凭据和授权要求，不默认需要自建后端 |
| Q-07 | 受限平台是否允许随包核心 | 影响 iOS、原生鸿蒙及发行渠道方案，不可默认接受 |
| Q-08 | 商业化、发行渠道、默认源策略 | GPL 已接受，但这些产品和运营策略仍未确定 |
| Q-09 | 首版语言与备用语言顺序 | 建议简体中文／英文完整支持，具体回退配置在详细设计确定 |

未决项不阻止文档和只读架构分析，但其依赖实现不应擅自固化为已确认需求。
