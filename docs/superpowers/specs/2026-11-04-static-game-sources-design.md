# GG-002 静态 JSON 游戏源设计

日期：2026-11-04。状态：用户已确认静态 JSON 源路线，并于14:22确认本具体设计；作为 GG-002 实施与验收依据。

代码基线：`73100fda362b8622981daa2163cff1bc2d6a39cb`，首批原生游戏库已完成。本批沿用 C／C++、RetroArch 原生菜单和国际化机制。

## 1. 目标与范围

完成：添加 HTTPS 源地址 → 获取并校验目录 → 保存源 → 浏览游戏 → 查看详情 → 刷新／停用／移除源 → 断网查看上一次有效目录。

本批不下载游戏文件、不安装核心、不自动把在线条目写入本地播放列表，也不调用 IGDB 等第三方资料服务。下载地址和资料 ID 作为数据保存并展示，下载入库紧接着在后续任务中实施。在线游戏不显示“已安装”或“可运行”。

继续区分三类来源：游戏资源源、游戏资料源、核心仓库。本批实现游戏资源源；源自带名称和简介标为“来源提供”，不冒充权威元数据。

## 2. 方案比较与选择

| 路线 | 优点 | 成本 | 决定 |
|---|---|---|---|
| 静态 JSON 目录 | 普通 HTTPS 静态托管即可维护；容易复现和缓存 | 全量目录需有大小限制，不适合无限数据 | 用户已确认采用 |
| 固定 HTTP API | 服务端搜索、分页容易扩展 | 需要第三方部署服务、维护 API | 后续可独立扩展 |
| JavaScript 源 | 能适配不同站点 | 需要脚本运行环境、权限与生命周期设计 | 不纳入本批 |

## 3. 页面职责

原生主菜单新增独立“游戏源 / Game Sources”，保留“我的游戏库”及所有既有本地入口。

### 游戏源列表

- 添加游戏源：输入一个 HTTPS 目录地址。
- 已保存源：显示名称、启用状态、最后成功更新时间、当前状态。
- 没有源时给出简短引导，不内置商业游戏目录。
- kiosk 模式下可浏览已经启用的缓存源，隐藏添加、刷新、启停和移除等管理操作。

### 单个源页面

- 浏览游戏、刷新目录、启用／停用、查看源信息、移除源。
- 停用后不参与正常浏览入口和刷新；管理页仍能重新启用。
- 移除需确认，删除本源注册记录及目录缓存；不涉及本地游戏、存档或其他源。
- 正在刷新时仍可浏览旧目录，明确显示“更新中”。同一源不并发刷新。

### 游戏目录与详情

- 列表按显示名称排序，以稳定 ID 定位条目；同名不同平台保留为不同条目。
- 条目显示首选名称和主机平台。
- 详情展示名称、原文名、简介、地区／版本、来源名称，以及源提供的下载地址、大小、校验值和外部资料 ID（存在时）。
- 尚未实现下载时明确显示“仅浏览目录，本版暂不下载”，不提供无实际功能的下载按钮。
- 返回保留当前源与选中条目；刷新导致选中条目消失时返回目录，不引用失效内存。
- 首版只显示文本资料；图片 URL 可保存，图片下载和封面布局后续实施。

## 4. JSON v1 协议

单一 UTF-8 JSON 对象，不执行脚本。以下为协议示例，域名与游戏均为虚构，不请求该地址。

```json
{
  "schema_version": 1,
  "source": {
    "id": "example-homebrew",
    "name": "自制游戏示例源",
    "description": "用于说明 GameGate 源协议",
    "homepage": "https://example.org"
  },
  "games": [
    {
      "id": "demo-nes-v1",
      "platform": "nes",
      "original_language": "en",
      "original_name": "Example Homebrew",
      "localized": {
        "zh-Hans": {
          "name": "示例自制游戏",
          "description": "示例介绍，不对应真实游戏。"
        },
        "en": {
          "name": "Example Homebrew",
          "description": "An illustrative catalog entry."
        }
      },
      "region": "world",
      "version": "1.0",
      "download": {
        "url": "https://example.org/games/demo.nes",
        "size_bytes": 40960,
        "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
      },
      "external_ids": {
        "igdb": "12345"
      }
    }
  ]
}
```

### 必填与身份

- 根对象：schema_version（整数1）、source（对象）、games（数组）。games 可为空。
- source：id、name 必填，description／homepage 可选。
- 游戏：id、platform、original_name 必填；其他字段可选。
- 源内游戏 ID 唯一，禁止按名称去重或合并。
- 源 ID 和游戏 ID 限 ASCII 字母、数字、点、下划线、短横线，长度1–128。
- 客户端为注册源生成独立本地实例 ID；远端 source.id 只是声明身份，不作为缓存路径。两个不同地址声明相同源 ID，不覆盖或自动合并。
- 重复添加同一地址提示“已添加”。只做 URL 的安全规范化，不删除或重排查询参数。
- 已注册源刷新后 source.id 改变，拒绝覆盖旧目录并提示身份变化；明确移除后重新添加才能接受。
- 外部资料 ID 以提供者命名空间保存。本批不据外部 ID 合并作品。

### 多语言

- localized 的键为语言标签，例如 en、ja、zh-Hans、zh-Hant。
- 本批沿用当前界面语言作为资料偏好，不新增独立偏好设置页。
- 名称与简介分别回退：当前语言 → 英文 → 原始语言；名称最终回退 original_name，简介最终显示“暂无简介”。
- 不通过简繁转换冒充地区译名，不机器翻译名称，不更改 ROM 语言。
- 资料模型保留多语言文本和实际来源，为后续独立资料偏好、元数据补充及手工覆盖保留边界。

### 下载与平台信息

- download 可缺失；缺失时详情显示“未提供下载地址”。存在时 url 必填。
- size_bytes 是可选非负整数；缺失表示未知，0是合法大小，不与未知混淆。
- sha256 可选；存在时必须是64位十六进制。大小、校验和可下载标记不代表已验证资源授权或内容。
- URL 仅接受绝对 HTTPS 地址，不接受 file、javascript 或含用户名密码的 URL；拒绝碎片段和控制字符。
- 初始已识别 platform 代码：nes、gb、gbc、gba、snes、megadrive。未知代码保留并显示“未识别平台”，不误判设备支持或自动选择核心。
- region／version 是描述信息，不决定文件身份或覆盖旧游戏。

### 限制与容错

- 源注册数最多32个；单目录最大4 MiB（按响应解码后的 JSON 数据计），最多5000个游戏，嵌套深度最多16。
- 每条游戏最多16种语言；名称最多256个 UTF-8 字节，简介最多8192字节，URL最多2048字节；字段限制超出即拒绝该次目录。
- 编码错误、重复 ID、重复关键字段、字段类型错误、未知协议版本拒绝整个刷新，不用一份悄悄丢失条目的目录覆盖旧缓存。
- 未识别扩展字段可跳过，但仍受整体字节数、深度及条目上限限制。
- 大小限制必须在接收期间或采用有界传输策略执行，不能无界加载后才检查；具体网络接口需按此约束选取。

## 5. 状态、持久化与异步处理

- 本地注册表记录本地实例 ID、URL、source.id、显示名称、enabled、最后成功刷新时间和最近错误状态。
- 文件位置使用应用配置目录下专用 gamegate/sources 子目录，通过现有路径／VFS 能力解析，不依赖开发机绝对路径。
- source URL 可能含访问令牌：错误提示及普通日志不回显查询参数，不在示例或截图中泄露用户地址。
- 第一次添加：先取回、校验并写入缓存，成功后再登记为可用；失败不留下伪成功记录。
- 刷新：旧目录继续可用；新目录接收到临时文件，完整校验后替换，失败清理临时文件并保留旧目录。
- 使用注册表修订号／源代次识别回调。刷新中停用或移除后，过期回调不能重新保存已删除源或恢复启用。
- 网络获取、缓存读取和 JSON 解析需分帧或有界执行，保留取消和退出清理路径；不能假设后台线程始终开启。
- 注册表损坏时不静默覆盖原文件；提示恢复，保留证据文件。缓存损坏只影响本源，不影响本地游戏和其他源。
- 原生 HTTPS 证书验证保持开启；不因测试便利关闭证书验证或允许降级HTTP。
- 本批无 Cookie／账号登录、任意请求头和来源脚本。鉴权扩展后续独立设计。

## 7. 验收标准

| 场景 | 通过标准 |
|---|---|
| 合法源 | 从界面添加 HTTPS 源，显示来源、目录和详情 |
| 无效源 | 错误版本、类型、重复ID、非法URL、超限被拒绝，有明确原因 |
| 断网／刷新失败 | 旧目录仍可浏览，标注缓存和失败状态，不影响本地游戏 |
| 停用／移除 | 停用可重新启用，移除不删除本地游戏；并发回调不复活源 |
| 重启 | 保存的源与最后有效目录可恢复，注册和缓存损坏分别处理 |
| 多语言 | 中文／英文与缺译回退逐字段验证，原文和资料语言可追溯 |
| 身份一致性 | 不同源同名条目不误合并，刷新 source.id 改变被拒绝 |
| 限流量 | 超大响应及时终止，不因声明 Content-Length 缺失就无限接收 |
| 生命周期 | 导航离开、刷新结束、应用退出不会访问已释放对象；无后台线程时仍有界 |
| kiosk | 已启用源可浏览，管理修改入口不可用 |
| 本地回归 | 第一批游戏库、导入、集合加载和返回行为不受影响 |

测试资源使用自制目录、无商业ROM，独立目录与可控服务；网络测试服务的启动和公开可访问性只限测试用途。无法验证的系统及工具链明确记录，不宣称六端通过。
