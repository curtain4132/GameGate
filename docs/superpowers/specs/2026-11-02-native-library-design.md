# GameGate 首批原生游戏库设计

- 日期：2026-11-02
- 任务：GG-001
- 状态：用户已通过选择题确认“按推荐方案实现”：沿用 RetroArch 原生菜单，新增“我的游戏库”，复用本地导入、核心选择、应用内加载，新增中英文文案，验证关闭内容回到列表。
- 基线：9fa533cecd2ffddcfc4fa29fe07fea320577442f。

## 1. 范围与选择

采用现有原生菜单和播放列表导航，新增 GameGate 游戏库入口，组织本地导入和已有游戏集合。不引入新 UI 框架，不另造与播放列表并行的数据存储。

比较过的方向：

- 原生菜单入口与现有列表复用：本轮采用，改动集中，可保留输入、渲染和加载能力。
- 全新封面首页与独立界面：本轮不实施，后续需要单独交互设计。
- 独立游戏库数据库与自定义启动器：本轮不实施，避免在作品资料模型尚未确定时复制上游存储与生命周期逻辑。

本批是本地使用流程入口，不代表游戏源、下载、元数据和完整平台 UI 已完成。

## 2. 用户流程

1. 主菜单可见“我的游戏库 / My Game Library”。
2. 进入游戏库后可访问本地导入与现有用户游戏集合；沿用原有收藏和历史能力，不复制这些文件。
3. 本地导入通过现有导入／扫描入口完成；新用户无列表时仍能找到导入操作。
4. 打开集合，选择游戏；已有有效核心时使用原有加载流程，未指定核心时沿用原有核心选择。
5. 游戏运行在当前 App 内；保留既有快捷菜单与输入功能。
6. 从集合启动的内容关闭后回到相应集合或其原有条目操作上下文，保留继续浏览路径；不能错误退回无关主菜单或产生失效条目。

显示受原有 kiosk 与列表可见性配置约束，不绕过用户既有隐藏设置。

## 3. 数据与接口

- 不新增游戏库总表或复制已有 .lpl；新入口作为集合导航的组织层。
- 真正导入、去重、持久化、核心关联使用上游 playlist／task 路径。
- 历史、收藏与用户集合保持各自原有文件路径，不共享覆盖。
- 不用标题作为作品唯一身份，不在本批确定后续元数据数据库。
- 未找到内容或核心时沿用现有错误提示及选择流程，不将失败状态写成成功。

主菜单构建位于 menu/menu_displaylist.c，条目动作绑定位于 menu/cbs/menu_cbs_ok.c，加载任务位于 tasks/task_content.c；具体修改清单以实现者核查后最小必要范围为准。

## 4. 国际化

- 新文案提供英文和简体中文，其他语言缺失时回退英文。
- 沿用 msg_hash 查询机制，文案不在 UI 代码中硬编码。
- 原生生成语言表不能手工编辑；采用可重复的源文件与生成／覆盖入口，在不访问上游 Crowdin 管理账号的情况下维护 GameGate 自有翻译。
- 新增 label 如涉及生成区，运行原有生成器，不手改生成 blob。

## 5. 生命周期与平台边界

- 保持现有 playlist entry 的导航身份和 deferred_path 等上下文，尽量不改运行循环。
- 返回列表的验收使用默认不退出应用的配置；用户显式开启 quit_on_close_content 时继续尊重原有退出行为，不静默覆盖该设置。
- 只有现有逻辑确实无法满足返回行为时，才针对具体导航状态作最小改动；禁止大范围重构。
- Windows x64 是本轮实际验证端，不承诺其他端已验收。
- 不直接用 stdio 路径判断替代上游 VFS；保留 Android URI、便携路径等原有能力。
- 导入和目录遍历沿用任务预算，不新增主线程阻塞或锁。

## 6. 验收

1. 英文与简体中文均能看到新增游戏库入口与必要说明。
2. 空游戏库有导入入口，已有集合可继续打开。
3. 列表条目、标签与核心关联不被入口改动破坏。
4. 已配置核心、需要选择核心、内容／核心失效分别走正确分支。
5. 从集合加载内容后，关闭内容返回原列表相关上下文，可再次选择启动。
6. 原有收藏／历史／列表入口保持工作，kiosk 不因新入口被绕过。
7. 运行必要 Windows 构建、生成一致性及适用回归；缺乏环境的项目如实记录，不用静态检查替代交互验证。
