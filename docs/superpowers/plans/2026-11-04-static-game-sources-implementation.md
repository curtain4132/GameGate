# GG-002 实施与验收顺序

基线：73100fda362b8622981daa2163cff1bc2d6a39cb。工作分支：feat/static-game-sources。

对应已确认设计：[静态 JSON 游戏源](../specs/2026-11-04-static-game-sources-design.md)。

## A：协议模型与解析

- 生产模块位于 gamegate/catalog.c/h，尽量独立于菜单和网络状态。
- 复用 rjson 的严格编码与事件读取，分片解析，不改共享库。
- 明确 parser、目录、字符串及查询结果的生命周期；出错或取消时不发布半成品。
- 稳定 ID、类型、限制、URL、uint64 大小、语言回退作为真实 C 测试对象。
- 使用 MSVC 单独构建实际解析器；提供可复用的编译入口，产物只写 artifacts。
- 主 Agent 独立复验，Claude 只读检查协议和边界。冻结该包接口后进入B。

## B：注册、传输与缓存

- 先解决请求大小上限、TLS建连/取消和重定向边界，再决定复用现有网络接口的具体方式。
- 不能因为调用task_push_http_transfer就宣称全程非阻塞：当前net_http TLS握手会同步等待。
- 不能把全局连接池并发交给多个独立worker：net_http声明单一驱动线程所有权。
- 每源使用本地实例ID与修订代次，删除或停用后过期结果不能重新发布。
- 获取、缓存读写、解析和UI发布是独立状态；原有效目录在新结果完整校验成功前保留。
- 增加可控网络测试：超限无Content-Length、错误/过期证书、HTTPS降级重定向、超时、取消、移除、刷新失败与缓存恢复。
- 证书验证保持开启；本地测试使用限定测试信任根，不修改用户或系统全局信任配置。
- B主验收和审查闭环后进入C。

## C：原生菜单

- 游戏源列表、地址输入、源详情/管理、游戏目录、游戏详情，统一现有消息注册。
- 使用本地实例ID和条目ID重新解析选中项，避免刷新后访问旧指针。
- 网络回调不直接操作释放的菜单结构，菜单从当前服务状态重建。
- 中英文及缺译回退，kiosk禁止管理但可看已启用缓存。
- 使用真实stdin MENU接口或原生harness驱动交互；不把源码关键字搜索算作功能测试。

## 集成交付

- 从添加真实HTTPS源到目录详情浏览的一条完整链路，重启/离线/刷新错误/停用与移除分别验证。
- 第一批本地游戏库、现有播放列表和原生运行返回路径做影响范围回归。
- Windows Release x64构建和已适用测试通过后记录结果；Linux/MinGW/其他设备无环境不声称通过。
- 最终审查包含生产代码、测试和交付说明，审查前后保存内容、SHA-256和完整diff。
- 同一任务链最多两轮修复，拆包不重置计数。不执行推送。

Codex负责实现和修复，主Agent负责架构取舍、文档、基线与独立验收，Claude负责只读审查。普通助手只可进行无写域的研究。具体调用ID、命令及结果维护在仓库progress.md。
